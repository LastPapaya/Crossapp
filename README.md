# CrossApp — Multi-project Solution (.NET 9)

## Предметна область
**Ігровий інвентар та торгівля**
* **Сутності:** 
  * `Player` (Гравець) — нікнейм, рівень, внутрішньоігровий баланс.
  * `Item` (Предмет) — назва, рідкісність, базова цінність, атрибути.
  * `InventorySlot` (Слот інвентарю) — прив'язка предмета до гравця, кількість, стан.
  * `TradeTransaction` (Угода торгівлі) — продавець, покупець, предмет, ціна, дата транзакції.
* **Призначення:** Система для управління персональними інвентарями гравців, обліку ігрових предметів та проведення внутрішньоігрових торговельних угод.

## Лабораторна робота 4. Доменна модель: сутності, інваріанти, інкапсуляція

### Перелік реалізованих інваріантів:
1. **Обов'язкові рядкові поля**: Ідентифікатор слоту, назва предмета та його рідкісність не можуть бути порожніми або складатися лише з пробілів (`ArgumentException`).
2. **Коректність початкових значень**: Кількість предметів у стаці та їх базова вартість не можуть бути від'ємними під час створення об'єкта (`ArgumentOutOfRangeException`).
3. **Валідність операцій зміни кількості**: Додавання чи видалення предметів має виконуватися строго додатним числом (`ArgumentOutOfRangeException`)
4. **Контроль залишку в інвентарі**: Неможливо видалити з інвентарю більше предметів, ніж є в наявності у відповідному слоті (`InvalidOperationException`)

## Лабораторна робота 5. Сервісний шар: інтерфейси, два сховища, ручний DI

- **Інтерфейс сховища**: `IInventoryStore`
- **Реалізації сховища**: `InMemoryInventoryStore` (у пам'яті) та `FileInventoryStore` (файлове сховище з JSON-серіалізацією)
- **Сервісний шар**: `InventoryService` (реалізує бізнес-операції над сутностями через інтерфейс)
- **Composition Root**: реалізовано в `src/Cli/Program.cs` із підтримкою перемикання через аргумент `--file`.
